## 저장 방식 비교와 결정

기존 방식은 매 변경마다 저장과 이력 보관이 진행되어 긴 문서에서 작업량이 증가할 수 있었습니다. 저장 때문에 실제 글자가 빠졌다는 인과관계는 확인되지 않았습니다. 사용자가 제안한 방식에 따라 **마지막 변경 후 2초간 입력이 없을 때 저장**합니다. 입력이 재개되면 타이머를 다시 시작합니다. 항목/메뉴 전환, 수동 저장, 종료 요청에서는 남은 변경을 먼저 저장합니다. 저장 중 새 입력이 생기면 후속 자동저장도 다시 2초 대기합니다.

변경 이력은 입력 중 매 키마다 생성하지 않고 실제 저장 시점에 남깁니다. 이력 기능 자체를 제거할 근거는 없어 유지하며 기존 보관 개수 설정도 유지합니다. 저장 버튼은 입력 중 처음 미저장 상태가 된 때와 저장 완료 때만 바뀌며, 매 글자마다 왕복하지 않습니다.

## 동일 문장 반복 검사

문장: **오늘은 새로운 캐릭터의 성격과 이야기를 차분하게 정리합니다.**

- 기존 35,919자 문서 뒤에 같은 문장을 중간 휴식 없이 5회 연속 입력합니다.
- 자동저장 켜짐/꺼짐에서 각각 5회, 총 10회 비교합니다.
- 한글 초성→초중성→종성 조합 단계를 매 40ms 가상 시간 간격으로 전달합니다. 모든 중간 상태와 완성 문장을 비교합니다.
- 본문·포커스·컨트롤러 유지, 불필요한 IME 재연결/내용 덮어쓰기 없음, 입력 중 저장 리비전 변화 없음, 2초 경계 이전 저장 없음, 최종 저장 및 재열기 일치를 검사합니다.
- 이는 Flutter TextInput 경계에서 조합 이벤트를 전달하는 자동 검사입니다. 실제 Windows IME의 물리 키 입력을 재현한 실험과 동일하지 않습니다. 사용자의 간헐적 증상이 완전히 해결됐다고 단정하지 않습니다.
